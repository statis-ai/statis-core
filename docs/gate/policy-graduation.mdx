## What is graduation?

Graduation turns human approvals into policy rules so you don't have to approve the same
action forever.

**Trigger:** When the same `action_type` + `canonical_args_hash` has been **approved 3 times**
within a **48-hour window**, Statis surfaces a rule suggestion in the console and via webhook.

## The trigger in detail

The graduation key is:

```
graduation_key = sha256(action_type + ":" + canonical_args_hash)
```

Three approvals with the same `graduation_key` → rule generated. Approvals by different
humans, across different agents, all count toward the threshold.

## The generated rule

Given three approvals of `stripe_refund` with `cents <= 5000`:

```yaml
# Auto-generated by Statis policy graduation
# 3 approvals in 48h window — 2026-04-27T14:00:00Z to 2026-04-27T18:33:12Z
rule: stripe_refund_auto_v1
when:
  action_type: stripe_refund
  args.cents:
    lte: 5000
then: APPROVE
priority: 50
```

The rule is a **suggestion** — it does not activate until you run `statis apply`.

## Applying a suggested rule

```bash
statis rules list --pending

# Output:
# stripe_refund_auto_v1  PENDING  created 2 minutes ago
#   when: action_type=stripe_refund, args.cents <= 5000

statis apply stripe_refund_auto_v1
# Applied. Future calls matching this rule will be APPROVED automatically.
```

Or edit before applying:

```bash
statis rules edit stripe_refund_auto_v1
# Opens in $EDITOR
# Change the threshold, add conditions, rename the rule
statis apply stripe_refund_auto_v1
```

## Noise handling

If your `action_type` has non-deterministic arguments (timestamps, UUIDs, request IDs),
the canonical hash will differ on every call — graduation won't trigger.

Fix: supply a `graduation_key` override that strips noise:

```python
@gate(
    action_type="stripe_refund",
    graduation_key=lambda args: f"stripe_refund:cents_le_10k:{args['cents'] // 10000}"
)
def refund(charge_id: str, cents: int) -> dict:
    ...
```

This groups all refunds under $100 into the same graduation bucket, regardless of `charge_id`.

## Disabling graduation

Per-gate:

```python
@gate(action_type="one_off_action", graduation=False)
def one_off(...): ...
```

Account-wide: disable in console under Settings → Policy → Graduation.

## Console view

The console shows pending graduation suggestions under **Policies → Graduation**. Each
suggestion shows:

- The 3 approvals that triggered it (who approved, when, what args)
- The generated YAML rule
- Apply / Edit / Dismiss actions
