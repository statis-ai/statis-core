---
title: "Create Policy Rule"
api: "POST /policy-rules"
description: "Create a new policy rule for the authenticated tenant."
---

## Request body

<ParamField body="rule_id" type="string" required>
  Unique identifier for the rule within the tenant.
</ParamField>

<ParamField body="rule_version" type="string">
  Version string. Defaults to `"1"`.
</ParamField>

<ParamField body="action_type" type="string" required>
  The action type this rule applies to (e.g. `"retention_offer"`).
</ParamField>

<ParamField body="conditions" type="object" required>
  Condition map evaluated against entity state. Keys are condition names, values are expected thresholds or booleans.
</ParamField>

<ParamField body="decision" type="string">
  Decision when all conditions pass. Defaults to `"APPROVED"`. Can also be `"DENIED"` or `"ESCALATED"`.
</ParamField>

<ParamField body="priority" type="integer">
  Higher priority rules are evaluated first. Defaults to `0`.
</ParamField>

<ParamField body="active" type="boolean">
  Whether the rule is active. Defaults to `true`.
</ParamField>

<ParamField body="description" type="string" optional>
  Human-readable description of the rule.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST https://api.statis.dev/policy-rules \
  -H "X-API-Key: st_..." \
  -H "Content-Type: application/json" \
  -d '{

    "action_type": "retention_offer",
    "conditions": {
      "churn_risk": true,
      "min_ltv": 1000
    },
    "decision": "APPROVED",
    "priority": 10,
    "description": "Auto-approve retention offers for high-LTV churning accounts"
  }'
```
